# PDF Overlay MVP

Локальное веб-приложение на React + TypeScript для наложения печати и подписи на PDF прямо в браузере.

## Что умеет MVP

- Загружать исходный PDF.
- Загружать PNG-печать и PNG-подпись.
- Визуально размещать, менять размер и вращать элементы на нужной странице.
- Сохранять шаблон под именем.
- Открывать другой PDF и применять сохранённый шаблон.
- Обрабатывать очередь из нескольких PDF, удалять лишние файлы и продолжать пакет при ошибке отдельного документа.
- После первого полного открытия заранее кэшировать интерфейс и весь PDF-движок для работы без интернета.
- Показывать предпросмотр результата.
- Экспортировать готовый PDF.
- Пытаться облегчить итоговый файл безопасными браузерными методами:
  - `pdf-lib` сохраняет PDF с объектными потоками.
  - Большие PNG-накладки можно автоматически уменьшить по длинной стороне.

## Что не обещаю

- Это не полноценный компрессор для сканов и тяжёлых PDF.
- Если нужен агрессивный и качественный сжатый результат для сложных документов, обычно нужен отдельный движок или серверный пайплайн.
- Поэтому здесь честно реализован только надёжный локальный минимум, без хрупких костылей.

## Про pdfme

Я отдельно проверил `pdfme` как возможную основу визуального редактора шаблонов.

Вывод для этого MVP:

- `pdfme` хорошо подходит, если шаблонный редактор строится вокруг его модели schema-based template editor.
- Для этого приложения важнее было быстро и стабильно собрать именно локальный workflow по обработке произвольного PDF, с точным управлением страницами и координатами.
- Поэтому в MVP ядро сделано на `pdf-lib`, а интерфейс редактора написан специально под задачу.

Это не отказ от `pdfme` навсегда. Если захочешь, следующий шаг можно сделать гибридным: добавить pdfme как advanced editor для шаблонов, а финальный экспорт оставить на `pdf-lib`.

## Запуск

1. Установить зависимости.
2. Запустить dev-сервер.
3. Открыть приложение в браузере на компьютере или на iPhone в той же сети.

### Команды

```bash
pnpm install
pnpm dev
```

Для production-сборки:

```bash
pnpm build
pnpm preview
```

Для доступа с iPhone или другого устройства в той же Wi-Fi сети:

```bash
pnpm build
pnpm preview:lan
```

Откройте на телефоне адрес `Network`, который появится после запуска. Mac и iPhone должны быть в одной сети, а окно терминала должно оставаться открытым. PDF и изображения обрабатываются браузером устройства и не загружаются на сервер.

Важно: по обычному локальному HTTP приложение работает в Safari, но установка PWA и service worker на iPhone могут требовать HTTPS.

### Полностью офлайн на iPhone

1. Один раз откройте опубликованную HTTPS-версию при наличии интернета.
2. Дождитесь надписи `локально + офлайн` в блоке приватности.
3. В Safari нажмите `Поделиться` → `На экран «Домой»`.
4. После этого приложение открывается и обрабатывает локальные PDF без сети.

Первичная установка требует интернет. Safari может удалить кэш и локальные шаблоны при ручной очистке данных сайтов или критической нехватке памяти устройства.

## Архитектура

- `src/lib/pdf.ts`:
  - чтение размеров страниц;
  - browser-side render preview через `pdfjs-dist`;
  - browser-side export через `pdf-lib`;
  - безопасная оптимизация PNG-накладок.
- `src/components/PageCanvas.tsx`:
  - preview страниц;
  - drag/resize/rotate накладок.
- `src/lib/storage.ts`:
  - локальное хранение шаблонов в `localStorage`.
- `public/sw.js` и `public/manifest.webmanifest`:
  - базовая PWA-обвязка.

## Ограничения

- Шаблон хранит только то, что нужно для повторного применения: размеры страниц, координаты, PNG-накладки и настройки оптимизации.
- Плохой по качеству или слишком большой PNG лучше заменить нормальным исходником вручную.
- Для iPhone Safari PWA здесь есть минимальная оболочка, но реальные install/offline детали зависят от версии Safari.

## Проверка сценариев

Собирай и проверяй минимум так:

- Загрузить PDF.
- Загрузить печать и подпись.
- Поставить элементы на странице.
- Сохранить шаблон.
- Загрузить другой PDF.
- Применить шаблон.
- Убедиться, что предпросмотр и экспорт работают.
