# PDF Overlay MVP

Локальное веб-приложение на React + TypeScript для наложения печати и подписи на PDF прямо в браузере.

## Что умеет MVP

- Загружать исходный PDF.
- Загружать PNG-печать и PNG-подпись.
- Визуально размещать, менять размер и вращать элементы на нужной странице.
- Удалять выбранную печать или подпись со страницы; отдельно убирать загруженный PNG, сохраняя координаты блоков.
- Сохранять шаблон под именем.
- Хранить несколько шаблонов с PNG в IndexedDB, где доступно существенно больше места, чем в `localStorage`; прежние шаблоны переносятся автоматически.
- Обновлять выбранный шаблон или явно сохранять его как новый.
- PNG печати и подписи вместе с размещением хранятся в локальном шаблоне; после выбора шаблона их можно заменить, переместить и сохранить изменения.
- На каждой карточке шаблона есть сохраняемая галочка «Облегчать итоговый PDF»: она уменьшает PNG печати и подписи под их размер на странице, не меняя оригиналы в шаблоне.
- Открывать другой PDF и применять сохранённый шаблон.
- Переименовывать сохранённые шаблоны прямо в списке; ползунки выбранной печати или подписи раскрываются по запросу.
- Список шаблонов расположен вверху. Кнопка ⚡ на шаблоне принимает один или несколько PDF, сразу применяет сохранённые PNG/координаты и запускает скачивание PDF либо ZIP; если Safari не начнёт скачивание, рядом остаётся кнопка повторного экспорта.
- Обрабатывать очередь из нескольких PDF, удалять лишние файлы и продолжать пакет при ошибке отдельного документа.
- Применять один текущий шаблон ко всем PDF в очереди, пропуская страницы, которых нет в конкретном файле.
- Кнопкой «Обработать и сохранить PDF» сразу обрабатывать документы и запускать скачивание: один PDF либо ZIP для нескольких PDF.
- Имена экспортируемых PDF и ZIP содержат местную дату и время (`ГГГГ-ММ-ДД_ЧЧ-ММ-СС`), чтобы повторные выгрузки было легче различать.
- Предпросмотр доступен отдельной кнопкой без скачивания.
- После первого полного открытия заранее кэшировать интерфейс и весь PDF-движок для работы без интернета.
- При наличии сети обновлять оболочку PWA, а без сети открывать последнюю полностью сохранённую версию.
- Показывать предпросмотр результата.
- Экспортировать готовый PDF.
- Скрывать предыдущую страницу во время рендера, чтобы медленная загрузка скана не показывала ложный кадр.
- Перед обработкой автоматически перепаковывать PDF при включённой галочке; для нового пользователя она включена, затем выбор сохраняется в `localStorage` этого браузера. Если перепаковка не уменьшила файл, используется исходный PDF.
- Пытаться облегчить итоговый файл безопасными браузерными методами:
  - `pdf-lib` сохраняет PDF с объектными потоками.
  - PNG-накладки уменьшаются под фактический размер их блоков (до 300 dpi), только если это уменьшает PNG; неиспользуемые накладки в PDF не встраиваются.

## Что не обещаю

- Это не полноценный компрессор для сканов и тяжёлых PDF.
- Добавление печати и подписи может увеличить итоговый PDF; JPEG-сканы внутри исходника браузер не перекодирует.
- Галочка предварительной оптимизации перепаковывает структуру PDF, но не перекодирует встроенные JPEG-сканы.
- Если нужен агрессивный и качественный сжатый результат для сложных документов, обычно нужен отдельный движок или серверный пайплайн.
- Поэтому здесь честно реализован только надёжный локальный минимум, без хрупких костылей.

## Про pdfme

Я отдельно проверил `pdfme` как возможную основу визуального редактора шаблонов.

Вывод для этого MVP:

- `pdfme` хорошо подходит, если шаблонный редактор строится вокруг его модели schema-based template editor.
- Для этого приложения важнее было быстро и стабильно собрать именно локальный workflow по обработке произвольного PDF, с точным управлением страницами и координатами.
- Поэтому в MVP ядро сделано на `pdf-lib`, а интерфейс редактора написан специально под задачу.

Это не отказ от `pdfme` навсегда. Если захочешь, следующий шаг можно сделать гибридным: добавить pdfme как advanced editor для шаблонов, а финальный экспорт оставить на `pdf-lib`.

## Запуск

1. Установить зависимости.
2. Запустить dev-сервер.
3. Открыть приложение в браузере на компьютере или на iPhone в той же сети.

### Команды

```bash
pnpm install
pnpm dev
```

Для production-сборки:

```bash
pnpm build
pnpm test:offline
pnpm test:storage
pnpm preview
```

Для доступа с iPhone или другого устройства в той же Wi-Fi сети:

```bash
pnpm build
pnpm preview:lan
```

Откройте на телефоне адрес `Network`, который появится после запуска. Mac и iPhone должны быть в одной сети, а окно терминала должно оставаться открытым. PDF и изображения обрабатываются браузером устройства и не загружаются на сервер.

Важно: по обычному локальному HTTP приложение работает в Safari, но установка PWA и service worker на iPhone могут требовать HTTPS.

### Полностью офлайн на iPhone

1. Один раз откройте опубликованную HTTPS-версию при наличии интернета.
2. В Safari нажмите `Поделиться` → `На экран «Домой»`.
3. Откройте приложение именно с иконки на экране «Домой» при наличии интернета и дождитесь надписи `Офлайн готов.`. Так кэшируется не только экран, но и PDF-движок.
4. Включите авиарежим и проверьте, что приложение открывается с этой иконки, загружает PDF из «Файлов» и экспортирует результат.

Первичная установка и повторная загрузка после очистки кэша требуют интернет. Safari и приложение с экрана «Домой» могут иметь раздельные хранилища: шаблоны из Safari могут не появиться в установленном приложении. iOS может удалить кэш и локальные шаблоны при ручной очистке данных сайтов или нехватке памяти; абсолютной гарантии постоянного офлайна веб-приложение не даёт. Пока видна надпись `Готовлю офлайн...` или `Офлайн не готов.`, на работу без сети рассчитывать нельзя.

## Архитектура

- `src/lib/pdf.ts`:
  - чтение размеров страниц;
  - browser-side render preview через `pdfjs-dist`;
  - browser-side export через `pdf-lib`;
  - безопасная оптимизация PNG-накладок.
- `src/components/PageCanvas.tsx`:
  - preview страниц;
  - drag/resize/rotate накладок.
- `src/lib/storage.ts`:
  - локальное хранение шаблонов и PNG в IndexedDB с переносом из прежнего `localStorage`.
  - шаблоны, включая PNG-накладки, хранятся только в браузере этого устройства и этого адреса сайта; PDF-исходники не сохраняются в шаблоне.
- `src/lib/zip.ts`:
  - локальная сборка ZIP без повторного сжатия уже сжатых PDF и без серверной отправки.
- `vite.config.ts` генерирует `dist/sw.js` с атомарным кэшем версии, проверкой всех необходимых файлов и офлайн-навигацией.
- `src/lib/offline.ts` проверяет заполненность кэша до показа статуса готовности.
- `public/manifest.webmanifest` описывает устанавливаемое веб-приложение.

## iOS-приложение

Папка `ios/` содержит нативную оболочку Capacitor для iPhone и iPad. Она работает полностью из встроенных файлов приложения и объявляет поддержку PDF, поэтому в «Файлах», почте и других приложениях можно выбрать PDF → `Поделиться` → `PDF Overlay`. Один или несколько полученных PDF локально копируются в очередь приложения.

Для сборки нужен полный Xcode, установленный из App Store:

```bash
pnpm install
pnpm ios:sync
pnpm ios:open
```

В Xcode выберите target `App` → `Signing & Capabilities` → свою Apple Developer Team, подключите iPhone и нажмите Run. Идентификатор приложения: `com.nebuhtit.pdfoverlay`; при необходимости его можно заменить в настройках target.

После изменений React-кода перед каждой сборкой iOS выполняйте `pnpm ios:sync`. Входящие PDF находятся только в контейнере приложения и удаляются из папки приёма после загрузки в очередь.

## Ограничения

- Шаблон хранит только то, что нужно для повторного применения: размеры страниц, координаты, PNG-накладки и настройки оптимизации.
- Плохой по качеству или слишком большой PNG лучше заменить нормальным исходником вручную.
- Для iPhone Safari PWA здесь есть минимальная оболочка, но реальные install/offline детали зависят от версии Safari.

## Проверка сценариев

Собирай и проверяй минимум так:

- Загрузить PDF.
- Загрузить печать и подпись.
- Поставить элементы на странице.
- Сохранить шаблон.
- Загрузить другой PDF.
- Применить шаблон.
- Убедиться, что предпросмотр и экспорт работают.
